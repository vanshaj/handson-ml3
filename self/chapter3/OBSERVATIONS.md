## Interpretation

Confusion matrix layout is `[[TN, FP], [FN, TP]]`:
- **14407** true negatives — correctly predicted Not Elite.
- **29** false positives — predicted Elite, actually Not Elite.
- **51** false negatives — predicted Not Elite, actually Elite (missed).
- **344** true positives — correctly predicted Elite.

Only 395 of ~14,831 players (≈2.7%) are actually "Elite" — a strongly imbalanced dataset.
This is why precision/recall/F1 are tracked instead of relying on plain accuracy, which
would look deceptively high even for a model that just predicts "Not Elite" every time.

- **Precision 0.9223** — of all players the model *flagged* as Elite (373 = 344 + 29),
  92.2% actually were. Low false-alarm rate.
- **Recall 0.8709** — of all players who *are* actually Elite (395 = 344 + 51), the model
  caught 87.1% of them; it misses about 13% of genuine elite players.
- **F1-score 0.8958** — harmonic mean of precision and recall; ~0.90 indicates a balanced,
  solid result rather than one metric being optimized at the other's expense.

**Takeaway:** the model slightly favors precision over recall — when it predicts "Elite"
it's usually right, but it's more likely to miss a real elite player than to falsely
flag a non-elite one.

### `precision_recall_vs_threshold.png`

X-axis is the SGD decision score threshold above which a player is classified "Elite."

- At very negative thresholds: nearly everyone is classified Elite, so recall ≈ 1.0 but
  precision is very low (~0.02–0.05) — the "Elite" bucket is flooded with false positives.
- As the threshold rises, precision climbs sharply while recall falls off — the classic
  precision/recall tradeoff.
- The curves cross near threshold ≈ 0 (SGD's default decision boundary, i.e. what
  `sgd_clf.predict()` uses) at roughly precision ≈ 0.92, recall ≈ 0.87 — consistent with the
  `precision_score`/`recall_score` values reported above (`main.py:54-55`), since both are
  computed at the same default threshold.
- Past threshold ≈ 250–500, recall collapses toward 0 while precision approaches 1.0 — only
  the most confidently-scored players are labeled Elite, so nearly all of them really are,
  but very few are caught.

Use this plot to pick a different operating threshold if priorities change — e.g. shift left
to reduce missed elite players (fewer false negatives) at the cost of more false alarms, or
shift right for near-perfect precision at the cost of recall.

### `roc_curve.png`

Plots True Positive Rate (recall) vs False Positive Rate (fraction of non-elite players
wrongly flagged Elite) as the threshold sweeps, alongside the `[0,0]`–`[1,1]` random-guess
diagonal.

- The curve hugs the top-left corner — TPR reaches ~0.95+ while FPR is still near 0, meaning
  high recall is achievable with very few false positives on non-elite players.
- **AUC = 0.9989** (`main.py:69`, printed at `main.py:71-72`) — near-perfect separability.
  AUC is the probability that a randomly chosen actual-Elite player receives a higher decision
  score than a randomly chosen actual-Non-Elite player.

**Why ROC/AUC looks near-perfect while precision (0.9223) looks merely "good":** ROC/AUC is
insensitive to class imbalance (TPR and FPR are each normalized within their own class), while
precision is very sensitive to it. With only ~2.7% of players labeled "Elite," a small absolute
number of false positives (29) barely moves FPR but visibly drags down precision. This is why,
on imbalanced datasets like this one, the precision/recall curve is considered more informative
than the ROC curve even when AUC looks excellent.
